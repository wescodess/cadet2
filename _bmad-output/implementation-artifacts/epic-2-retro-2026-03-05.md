## Story-Level Signals (What We Learned)

## Story 2.1

- Strong foundation: canonical lifecycle vocabulary and server-owned boundaries prevented early contract drift.
- Key learning: test-mode controls must be explicitly guarded to avoid production misuse.
- Pattern: UI trust cues work best when status is text-first and lifecycle states are explicit.

## Story 2.2

- Strong foundation: deterministic evaluator and normalized persistence created reliable downstream inputs.
- Key learning: fail-fast behavior for missing profile snapshots is safer than synthetic fallbacks.
- Pattern: idempotency and explicit pending (`409`) states reduce ambiguity for consumers.

## Story 2.3

- Strong foundation: ranking pipeline and tier contracts made result ordering predictable and reusable.
- Key learning: ranking orchestration must be wired in runtime path, not only modeled in structure/tests.
- Pattern: successful standard runs must explicitly finalize lifecycle state, not rely on implied completion.

## Story 2.4

- Strong foundation: qualification metadata (`confidence`, `freshness`, `caveat`) improved trust signaling.
- Key learning: terminal mapping is nuanced; mixed-confidence outcomes should degrade, not over-promote.
- Pattern: refresh flows need defensive cross-store semantics and conservative defaults for legacy records.

## Cross-Story Patterns

### What Went Well

1. Incremental delivery sequence was effective: lifecycle -> evaluation -> ranking -> qualification/refresh.
2. Review loops improved outcome quality; major risks were detected before becoming production debt.
3. Contract discipline stayed strong: normalized payloads, owner-scoped access, provider internals hidden.
4. Trust posture improved each story: safer degradation, clearer caveats, fewer misleading outputs.

### What Was Painful

1. Runtime orchestration gaps surfaced after initial implementation more than once.
2. Integration coverage lagged behind risk in a few branches and required follow-up cycles.
3. Cross-store operations (snapshot + Convex run creation) introduced fragility that needed hardening.
4. Story artifact/file-list sync needed repeated cleanup.
