# Resolved registration authority: proposal for #176

Status: integration revision proposed on 2026-11-22; awaiting parent verification and owner decision. [Issue #176](https://github.com/wescodess/cadet2/issues/176) remains open. This note authorizes no implementation, review round, CI retry or merge.

## Proposed decision

Choose **a closed declaration convention over a finite transitive local-helper initialization graph, checked against the actual pinned resolver**: revised option B below, using only the resolution part of option A. Replace inference from an import spelling and an initial assignment with one atomic authority check over source identity, configuration scopes, every runtime import in the closure, generated mappings, positive initialization/value syntax and immutable exported bindings. Publish exemptions only when every part succeeds. Unknown authority is a public error, never an exemption or a new allowance.

The proved statement is deliberately limited:

> For these exact selected source bytes and configuration identities, this export follows the supported Convex declaration convention, and its registrar import resolves to the approved Convex 1.32.0 implementation through the supported generated mapping, if any.

This is **not a claim that arbitrary JavaScript has been evaluated soundly, that a deployment contains the function, or that the final runtime value remains registered**. Handler behavior, shared globals, SDK execution, runtime environment, load order and later invocation require their own evidence. Root defaults prove supported framework-slot declarations, not valid authentication, schema deployment, routes or scheduled jobs.

The owner must accept this proof boundary and authorize another bounded correction attempt explicitly before any PR170 implementation, integration commit or new review. If final native registration is required as the unused-code authority, choose option A with source-bound native analysis instead; do not describe this convention as an equivalent substitute. Native backend analysis is unavailable within this research authorization.

## Finite authority contract

### 1. Snapshot the complete supported source and scope closure

Start with the existing independent structural inventory, native entry-discoverability rules and exact root-default slots. For each claimed declaration/default and the canonical generated builder, traverse **every static runtime import**, including a named import used only in an opaque function or currently unused. Importing a module initializes it regardless of whether its exported function is called. A tree-shaken native bundle is not permission to skip a syntactically present dependency. Memoize by `(canonical source identity, platform)`; finish the graph before publishing any exemption.

Local authority inputs must be tracked regular `.ts`/`.js` ESM source within the repository and the existing structural source population. This includes `shared/utils/governanceAudit.ts`; being outside `convex/` grants no exemption and is not a reason to inline it. The canonical generated server is an explicit additional input despite its normal population exclusion. Bind its runtime bytes and generated companions; declarations in `.d.ts` alone cannot prove runtime registration. The generated API's independent snapshot does not grant another framework entry or authorize its `componentsGeneric()` initialization as an application recipe.

Record Git mode/blob, repository-relative path, realpath, content SHA-256 and canonical regular-file/directory ancestry. Reject untracked/ignored authority inputs, source/configuration symlinks, aliases, dangling links, nonregular files, outside-repository targets, case mismatches and ambiguous `.ts`/`.js` siblings. Extensionless or `.js` local specifiers may select one canonical `.ts`/`.js` source only through actual resolution. No suffix guessing establishes binding authority. Ordinary ignored/untracked inputs retain the existing population policy; none becomes an implicit framework consumer.

For each importer **and resolved local target**, walk filesystem ancestry independently of Git/ignore rules. Observe both `tsconfig.json` and `jsconfig.json`, all package scopes and component/config candidates. Continue above the repository for ambient scopes the resolver can consult. Do not stop at the nearest package: the retained inherited-browser control survives a nearer empty package. Bind relevant presence/bytes and absence witnesses, including alternative builder/default paths, missing compiler files, descendant package/compiler scopes and earlier private package-search roots.

### 2. Resolve runtime edges and lexical binding provenance

Use Convex-owned esbuild0.27.0 with the pinned `innerEsbuild` ESM/ESNext/automatic-JSX resolution options, explicit `convex,module` conditions and the actual importer/`resolveDir`, `kind:import-statement`. Do not supply benign `tsconfigRaw`, aliases, externalization, application resolver plugins or invented conditions. Unknown resolver warnings/errors and disabled/external/namespace-redirected results fail. An empty-build `build.resolve` observer establishes targets without loading application modules; it is not function analysis.

Use browser mode for isolate entries. A supported leading `use node` action/http-action requires Node-mode edges throughout its closure; query/mutation declarations there fail. Resolve a shared helper separately for every importing platform. The actual graphs contain no `use node` entry. Additional Node-mode observations here establish resolver behavior only; public Node action/module controls remain required before implementation can claim support.

Every local import must be a relative static named ESM import resolving to a tracked canonical local module in the complete closure. The only supported local default import is the exact root schema slot for the bounded schema projection below. Runtime barrels, export-from/star exports, namespace/default helper imports, side-effect-only imports, CommonJS/import-equals, `#imports` and arbitrary bare-package imports fail. Type-only imports/exports are recorded as erased and grant no runtime authority; mixed imports retain every value specifier. Empty value imports (`import {}`) are unsupported side-effect imports, not erased-type witnesses. Erased type references are excluded from value-use restrictions and cannot confer a runtime role. A runtime reexport cannot be mislabeled type-only. Local named exports of ordinary declared functions or const data, including one explicit local export alias, are allowed and remain ordinary Knip obligations.

For each import specifier bind the **local lexical symbol** to the exact target module's exported declaration, not to its identifier text. Retain declaration span/source hash, import and export names, scope identity and any permitted local export edge. A helper called `query`, a shadowed `v`, or an ordinary module reexporting a registrar cannot become the canonical registrar. This is a finite export table plus local binder, not an open-ended assignment or wrapper tracer. Scope shadowing must be distinguished from writes to the protected import.

Canonical SDK import roles are explicit API roles, not application helper-name exceptions:

| Resolved root / exported binding | Role and permitted use |
| --- | --- |

| Same index: `paginationOptsValidator` | Trusted SDK object-validator data, supported directly in args and through the bounded `.fields` projection. Bind its canonical export/leaf identity to the selected package; do not assume every SDK export is validator data. |

Follow the selected SDK's own export table to its approved leaves, including `server/pagination.js`; bind root/leaf digests and lock/package identities in the receipt. SDK/auth implementation and their installed dependency closure, tooling and the named runtime intrinsics are explicitly trusted. This design neither proves their global purity nor sandboxes edited tooling. Application imports cannot extend that trusted set merely by residing in `node_modules` or carrying the same package/version text.

No emitted implicit dependency may bypass this graph. Version1 admits plain `.ts`/`.js` ESM only and rejects JSX anywhere in the module, including dormant bodies, decorators, runtime namespaces/enums, import attributes and emit-affecting JSX/import-source pragmas. Type/interface/ambient `declare` forms must erase without emit; the incoming `declare const process` is such a declaration. Dynamic import/require/eval or unknown calls during initialization fail. Their invocation-time behavior inside an otherwise dormant body remains outside the convention proof, subject to the protected-reference restrictions below.

### 3. Positive initialization, value and reference language

Apply this grammar to **every complete local module in the closure**, not only the imported symbol or registration statement. Admit static supported imports/exports, erased declarations, ordinary dormant function declarations/arrow or function expressions, `const` bindings, exact root defaults and a permitted runtime directive. No mutable top-level runtime `let`/`var`, arbitrary expression statements, classes/static blocks, getters/setters, computed keys, branches/loops/try blocks, IIFEs, top-level await or unknown initialization. An unused imported binding does not excuse effects in its module.

Use the following finite value roles. Types/assertions/satisfies/parentheses erase; a TypeScript annotation cannot confer a role. Initializer dependencies must be acyclic, locally earlier where evaluation requires it, and exported immutable bindings across the acyclic module graph.

| Role | Positive construction/reference grammar |
| --- | --- |
| Plain data | Primitive literals; finite literal arrays and plain object property assignments with static identifier/string keys; references to already admitted const data. Reject accessors, arbitrary computed keys, duplicate/prototype-sensitive keys, unknown expressions and general spreads. Declaration-relevant data is protected transitively through each reference. |
| Dormant function | An ordinary declared function or uninvoked arrow/function expression. Its parameter defaults and body execute only on invocation. A local/imported dormant helper may be called from a handler/helper body, never to compute a module initializer, validator, handler or registration. No effect/purity conclusion is drawn from its body. |
| Ordinary helper state | Const state recursively consisting of plain data, arrays/plain objects of such state, references to earlier such const state, unshadowed `new Set(literal-data-array)` and zero-argument `new TextEncoder()`. These are finite trusted-intrinsic recipes, needed by lifecycle sets and the actual shared audit encoder. No initializer-time method call, custom constructor or constructor argument callback. Their invocation-time internal state/use is ordinary application behavior, not declared deeply immutable or registered. |
| Validator | Calls to canonical `v.any,array,boolean,id,literal,null,number,object,optional,string,union` with recursively appropriate literal/data/validator operands and exact method arity. Reusable local/imported const validators retain binding provenance. Canonical `paginationOptsValidator` is the one observed imported SDK data recipe. Unknown SDK data/factories fail. |
| Field map / schema projection | Static `.fields` (or literal-string bracket equivalent) only on a proven object validator; static `schema.tables.<literal-table>.validator` only on the canonical root schema's admitted `defineSchema`/`defineTable` graph, followed by `.fields` when needed. Every table/field must exist in the finite recipe. Allow object spreads **only** of these proven field maps or recursively proven plain field maps into validator/args maps. Determine keys statically, reject duplicates/collisions, getters, unknown members, dynamic keys and general object/namespace spreading. No `.pick/.omit/.partial/.extend` inference is proposed. |
| Table/schema | Canonical `defineTable` over a proven field map/object validator with immediate literal `.index(name, fields)` chains, and `defineSchema` over a finite plain table map. Track the result role; never infer it from a property spelling. Unknown factory/chain calls fail. The trusted SDK supplies the semantics of its own construction/index operations. |
| Registration candidate | One direct canonical registrar call, exactly one supported definition object with `args`, optional `returns`, `handler`, or the supported direct function form. No unknown/duplicate keys, computed/accessor keys or registration-definition spread. Handler is a direct dormant function expression or a local/imported proven dormant function binding, never a factory call. |

Protected values are registrars/factories, `v`, candidate registrations, validators, schema/table/field-map objects and all data contributing to their recipes. Across the entire closure, including opaque bodies, enforce lexical use restrictions: registrar only as approved callee/generated edge; candidate only at its declaration and explicit export; protected data only at its finite construction/projection/declaration/export/import edges. No reassignment/update, property/bracket mutation/delete, namespace/property alias, `Object.assign`, reflection, passing to arbitrary helpers, storage in unknown objects, return/capture from dormant bodies or later value alias can escape that graph. Protected field projections remain protected aliases; `const` never means deep immutability. Reject an initializer that passes a validator to a dormant helper even if that helper appears harmless.

Ordinary helpers and ordinary state that do not feed a declaration remain application code. Their invocation-time reads, recursion, database/auth calls, callback/spread behavior and internal mutation are not interpreted. The actual `sourceActions`, `sourceSizeLimits` and `encoder` are const bindings feeding opaque helper bodies; they are not new registered exports or runtime-purity claims. The check still rejects their unsupported module initialization and binding reassignment. It does not attempt to prove the absence of string-based reflection, global/prototype poisoning or later dynamic behavior in arbitrary JavaScript. This is exactly where source convention proof ends.

Actual incoming initialization contains no validator/schema projection or field-map spread: its only initializer spread is the auth-provider recipe. Spreads in handlers/helpers, including pagination options and audit payloads, are invocation-time code and remain opaque. Bounded projections/spreads above are deliberately specified composition support, independently observed with canonical synthetic validators/schema, not invented evidence that PR159 currently needs source changes or already passes a checker.

Unknown initialization/import/value behavior anywhere in the closure produces a public authority error with the complete root-to-helper chain. Never evaluate the application to decide what it does, trust a helper by name, silently drop the edge, or return a partial exemption set.

### 4. Bind named exports immutably

Support these forms with static import aliases and erased wrappers:

```ts
import { queryGeneric as ask } from 'convex/server'
export const named = ask({ args: {}, handler: () => null })
```

```ts
import { query as ask } from './_generated/server'
import { requireAccess } from './lib/access'
const registered = ask({ args: {}, handler: async (ctx) => requireAccess(ctx) })
export { registered as named }
```

The helper's complete resolved module/transitive initialization must pass; `requireAccess` is illustrative, not a permitted-name list. The second candidate has one export edge to its original const initializer. Do not trace candidate assignment/value aliases. Reject `let`, `var`, destructuring, duplicate names/exports, namespace merges, mutation, arbitrary registrar reexports and candidate capture or consumption elsewhere. Ordinary registered defaults in function modules remain unsupported; an ordinary default earns no exemption.

Unrelated exported helpers/constants/defaults and helper files remain ordinary Knip debt. Authority traversal is **never** an application consumer, CLI entry or suppression. Preserve `includeEntryExports:true`, exact `(file, export-name)` filtering and native unused-export reports before authority filtering. A helper module with no registration earns zero registration exemptions even when traversed.

Accept exactly `query`, `internalQuery`, `mutation`, `internalMutation`, `action`, `internalAction`, `httpAction` mapped immutably to the corresponding canonical `*Generic`. Allow direct assignments or direct named SDK reexports here only. Reject extra/missing/duplicate/mutable mappings, runtime imports/statements and ambiguous siblings; apply all scope/target checks despite ordinary generated exclusion.
- Exact root `schema.ts`/`.js` default: admitted `defineSchema` graph as above, including the actual incoming14-table/49-index schema. Importing it for a supported projection binds this same complete graph; it does not turn arbitrary defaults/property chains into trusted data.
- Exact root `auth.config.ts`/`.js` default: finite plain providers object/array, empty providers or the current `...getAuthConfigProvider()` zero-argument recipe. Support the dev `process.env.CONVEX_SITE_URL ?? 'http://localhost:3000'` and incoming `process.env.CADET_AUTH_ISSUER ?? process.env.CONVEX_SITE_URL ?? 'http://localhost:3000'` initializer with the existing issuer/JWKS template. The incoming ambient `declare const process` erases. Read no environment value in this check. This specific trusted provider spread grants slot convention only, not auth validity, security, availability or deployment.
- Retain empty exact root `httpRouter()`, `cronJobs()`, `defineApp()` default positives, directly or through one immutable local default binding. Arbitrary route/schedule mutation and component `.use`/installation remain unsupported; none is present at these pins.
- Nested ordinary schema/auth/config defaults, hidden/skipped/multi-dot modules, copied/uninstalled components and unmounted trees retain ordinary debt. Discover component/default ambiguity from filesystem identity as well as tracked inventory. Named candidates must satisfy the pinned native entry-discoverability rules first.
