# Removal and isolation of legacy public surfaces

Decision date: 2026-11-17. Status: **answered-on-auto** for the private staging-pilot specification. Resolves [Define removal and isolation of legacy public surfaces](https://github.com/wescodess/cadet2/issues/48) under [Chart the Client and Representative portals for a staging pilot](https://github.com/wescodess/cadet2/issues/29). This record specifies removal, containment and replacement; it implements none of them and approves no deployment or data deletion.

**Close the legacy Client workspace before exposing the portals. Delete demos and deployed test processing, retain the existing internal admin with security fixes, and admit personalized Client content only through a Signed plan projection.** A login, completed run, admin review or feature flag cannot authorize an unsigned result. No portal flow calls an LLM. AI Search remains admin-only and separated from Client data. YouTube ingestion is frozen.

## Disposition rules and interim Client boundary

The inventory uses five dispositions: **delete** the registration/implementation; **make internal** with no browser-callable registration and only a specific trusted operation; **admin-only** with a live cadet2-admin grant at both the HTTP and backend boundary; **disabled until replacement** with no deployed activation of the old behavior; and **keep as is** where the surface conveys no legacy authority. A hidden link, client middleware, `NODE_ENV` condition or comment is never isolation.

**Disabled until replacement** means a server-owned deployment gate is false in preview, staging and production and enforced before any loader, SSR payload, subscription or mutation. Its absence is false; a query parameter, cookie, local storage, role string or browser flag cannot enable it. The legacy workspace is not enabled even for a signed-in Client. The environment decision owns concrete flag names and configuration; the old implementation is never an allowed enabled value. Keep its source only as reference while building the named replacement, then delete it. Self-serve personalized planning remains separately deferred and disabled; no release in this map enables it.

At containment, `/workspace` and every descendant return a generic unavailable/not-found state with **no legacy data fetch or payload**. Old API routes in the disabled groups return 404 before reading or starting work; delete their registrations at replacement cutover. Remove navigation, automatic start/refresh, polling and prefetch together. Already-open tabs gain no access through old HTTP or direct Convex calls. On auth/permission changes, clear private state, cancel subscriptions and discard late responses using the tenancy contract's scope epoch. Private pages/APIs are no-store and not prerendered; stale SSR payloads, history state or caches cannot act as authority.

The public entry and `/auth` may continue to offer authentication and a generic unavailable destination. They must not redirect to an active legacy results page. Once new portals ship, `/workspace` may redirect an admitted user to their permitted portal entry **without carrying a run payload**. Every old recommendation/history/compare/pathway deep link remains a 404, including `runId`, comparison IDs and refresh/source-run query variants. It never guesses a Signed plan from a legacy run ID. A future explicit alias may redirect only after current authority resolves an actual immutable Signed plan; adding that mapping requires its own reviewed contract, not a blanket compatibility redirect. New Client plan reads take Signed plan identity, not raw run identity. The surface-inventory decision chooses the new URLs and UI-gate batches.

All runs persisted at the baseline lack trusted provenance and therefore read as `unavailable: origin_unverified`; re-run through standard processing. Known nonstandard provenance is `origin_not_standard`. Migration, admin resolution, possession of the ID and signing cannot backfill either field. Restricted admin diagnostics may identify quarantined records and their provenance; they never turn them into ready assessments or unlock signing. Keep historical records restricted pending the existing retention/migration policies; removal of code does not authorize deleting rows, buckets, backups or credentials.
