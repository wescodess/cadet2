# Quality bar

`pnpm verify` runs the seven static rows owned by #23. CI runs it on every PR and push to `dev` (and retains the existing `main`, scheduled and manual triggers). Pre-commit checks formatting and lint on staged files, then runs the complete type ratchet. `pnpm install` installs the hook; linked worktrees get their own `core.hooksPath` setting.

Use Node 24 from `.nvmrc`, pnpm 9.12.3 from `packageManager`, and a frozen lockfile:

```sh
pnpm install --frozen-lockfile
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
export NUXT_PUBLIC_SITE_URL=http://127.0.0.1:3000
export CONVEX_SITE_URL=http://127.0.0.1:3000
pnpm verify
```

The secret above is disposable local verification configuration. CI generates its own value in the workflow; no GitHub secret or external account is required. `.env.example` documents auth, site and Convex variables. The production build does not require a live Convex deployment. Features that use Convex still need valid deployment URLs and credentials at runtime.

`verify` runs all row commands and prints their exit results, even if an earlier row fails. Infrastructure failures, unrecognized tool output, shallow history and expired allowances fail closed. ## Baselines and ratchets

The machine-readable manifests live in `scripts/quality/baselines/`. Counts are per file and diagnostic/rule so a reduction elsewhere cannot conceal an increase. Every new source file must be clean; the initial source inventory is fixed to `fe2b4a4e4f8b4b861fb5c92661b9e411a84ef0b3`.

Formatting exceptions are hashes of exact unchanged content. Changing an already unformatted file requires formatting it. Vendor workflow packages (`_bmad/`, `_bmad-output/`, agent/skill directories), generated Convex code, build outputs and the generated lockfile are excluded from the formatter; generated/vendor code is excluded from source lint. These exclusions do not remove those tracked files from secret scanning.

`baseline-policy.mjs` compares manifests to the integration merge-base and refuses added entries, higher counts, replaced hashes or extended dependency allowances. The first adoption creates the manifests; later PRs may only remove entries or lower counts. When paying down debt, lower the corresponding manifest in the same PR. Baseline writer flags are measurement helpers, never part of `verify` or CI, and do not authorize increases.

The dependency gate audits the entire dependency graph, including devDependencies. The initial raw audit reports 31 low, 146 moderate, 127 high and 10 critical findings. **The audit is not clean.** The gate permits only the recorded high/critical package/version/paths until expiry; a new path also fails. Lower severities are reported but do not fail this row. Licence exceptions include unknown metadata and copyleft tooling/runtime packages pending review under #22. Platform-specific lightningcss bindings use the same locked version and MPL-2.0 licence as their parent. Permitted licence identifiers and exact exceptions are explicit in the gate and manifest.

The secrets manifest contains digests, never secret values. Six findings are API-related rows containing SHA-256 hashes in the vendor file manifest; one is an expired-token example in vendor documentation. The eighth is a GCP API-key-shaped value in `server/utils/rag-ingestion-phase3.ts`, present in current code and history. Its validity/revocation has not been tested. It remains security debt requiring credential review/rotation under #22. An exception is bound to the rule, file and exact secret digest; replacing the value or adding it to a different file fails. Raw scanner reports are written to a private temporary directory and deleted; retained reports contain only digests.

The test-policy check parses TypeScript syntax rather than matching comments or strings. It recognizes `test`/`it`/`describe`/`suite`, named and namespace import aliases, bracket access and conditional skip modifiers. A new skip needs an issue reference in the title or immediately preceding comment. Focus is always forbidden, even with an issue reference.

Gitleaks is a native binary rather than a devDependency. If the exact version is already on `PATH`, the gate uses it. ## Budgets

Cognitive complexity is limited to 15, with the existing 17 violations ratcheted. Resource limits: two Vitest workers and a 20-minute Verify job. Performance, bundle size, boundaries, dead code, duplication, mutation and design ratchets belong to #24; they are not installed or claimed green here.

## Third parties without a sandbox

Static verification builds locally and runs existing isolated Vitest tests; it does not contact auth, Convex, Cloudflare or OpenRouter services. Dependency audit/installation use the npm registry, and the scanner installer uses official GitHub release assets. Journey provider behavior remains with #27.

## Waivers

None. Existing debt is recorded explicitly and ratcheted under the decisions for #23; passing a ratchet does not mean the inherited debt has been fixed.
