# Quality bar

`pnpm verify` runs the adopted static rows owned by #23 and the three structural rows owned by #24, the existing Vitest tests and production build, and #28's real legacy-access boundary suite after the build. CI runs it on every PR and push to `dev` (and retains the existing `main`, scheduled and manual triggers). Pre-commit checks formatting and lint on staged files, then runs the complete type ratchet. `pnpm install` installs the hook; linked worktrees get their own `core.hooksPath` setting.

Use Node 24 from `.nvmrc`, pnpm 9.12.3 from `packageManager`, and a frozen lockfile:

```sh
pnpm install --frozen-lockfile
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
export NUXT_PUBLIC_SITE_URL=http://127.0.0.1:3000
export CONVEX_SITE_URL=http://127.0.0.1:3000

```

The secret above is disposable local verification configuration. CI generates its own value in the workflow; no GitHub secret or external account is required. `.env.example` documents auth, site and Convex variables. The production build does not require a live Convex deployment. Features that use Convex still need valid deployment URLs and credentials at runtime.

## Baselines and ratchets

The machine-readable manifests live in `scripts/quality/baselines/`. Counts are per file and diagnostic/rule so a reduction elsewhere cannot conceal an increase. Every new source file must be clean; the initial source inventory is fixed to `fe2b4a4e4f8b4b861fb5c92661b9e411a84ef0b3`.

Formatting exceptions are hashes of exact unchanged content. Changing an already unformatted file requires formatting it. Vendor workflow packages (`_bmad/`, `_bmad-output/`, agent/skill directories), generated Convex code, build outputs, the generated lockfile, Markdown (`*.md`) and design records (`docs/design/**`: specimens, decisions and token files kept byte-identical as approval records; the app's own copies are formatted) are excluded from the formatter; generated/vendor code is excluded from source lint. These exclusions do not remove those tracked files from secret scanning.

`baseline-policy.mjs` validates explicit schemas for every manifest (including required keys, value types and unknown-key rejection), then compares all manifest entries to the merge-base of `HEAD` with both `QUALITY_BASE_REF` and `origin/dev` and refuses added entries, higher counts, replaced hashes or extended dependency allowances. The first adoption creates the manifests; later PRs may only remove entries or lower counts. A manifest absent from every compared base fails closed unless one base descends from the adoption commit `fe2b4a4`, so a PR into a branch without manifests, such as `main`, is still checked against `origin/dev`. Full runs also reject paid-down count allowances until their manifests are lowered to the reported current value. When paying down debt, lower the corresponding manifest in the same PR. Baseline writer flags are local measurement helpers and do not authorize increases. All quality commands reject writer flags (including `--write-baseline`, `--write`, `--fix`, and `--update-baseline`) whenever `CI` or `GITHUB_ACTIONS` is set, even to an empty value. CI pushes supply the pre-push commit as `QUALITY_BASE_REF`; PRs supply their target branch. The secrets diff uses that ref; baseline policy uses it together with `origin/dev`. Push runs use a per-commit concurrency group, so a later push never cancels the run that verifies its pre-push commit. An all-zero first-push ref fails closed because no prior commit exists; an explicit valid base is required. Checkout retains full history for these comparisons.

Inline ESLint rule configuration comments are forbidden, including ticketed forms. Ticketed `eslint-disable` directives remain supported.

The Convex compiler project restricts automatic ambient types to its own and the repository's `node_modules/@types` directories. Ancestor/home-directory packages cannot change the type or typed-lint baseline. A native compiler control rejects an ancestor-only ambient declaration and accepts the same declaration installed inside the project. This fences the verification environment without changing Convex implementations or baseline allowances.

The dependency gate audits the entire dependency graph, including devDependencies. The installed pnpm lock selects the virtual-store entries for licence inventory; orphaned directories from dependency changes are ignored, while selected manifests are still checked against the frozen lockfile. The initial raw audit reports 31 low, 146 moderate, 127 high and 10 critical findings. **The audit is not clean.** The gate permits only the recorded high/critical package/version/paths until expiry; a new path also fails. Lower severities are reported but do not fail this row. Licence exceptions include unknown metadata and copyleft tooling/runtime packages pending review under #22. Platform-specific lightningcss bindings use the same locked version and MPL-2.0 licence as their parent. Permitted licence identifiers and exact exceptions are explicit in the gate and manifest.

The secrets manifest contains digests, never secret values. Six findings are API-related rows containing SHA-256 hashes in the vendor file manifest; one is an expired-token example in vendor documentation. The eighth is a GCP API-key-shaped value in `server/utils/rag-ingestion-phase3.ts`, present in current code and history. Its validity/revocation has not been tested. It remains security debt requiring credential review/rotation under #22. An exception is bound to the rule, file and exact secret digest; replacing the value or adding it to a different file fails. Raw scanner reports are written to a private temporary directory and deleted; retained reports contain only digests.

The PR/push gate uses `--log-opts=HEAD`, so unrelated branches cannot change its result. Baseline exceptions absent from that history do not fail the gate; baseline policy still refuses added exceptions. The independent **Secrets (all branches)** job is configured to run `pnpm secrets:all` with `--log-opts=--all` on the weekly schedule and manual dispatch, using a full checkout of all branches. New findings fail that job and appear as rule/file/digest entries in its logs and the `secrets-all-branches` artifact, retained for 14 days. The job is skipped on PRs and pushes and is not a dependency of Verify. The schedule runs only once the workflow is on the default branch. The default branch must contain the workflow version that defines this job before weekly all-branches scans can run. Default-branch selection and workflow placement remain owner decisions.

The test-policy check runs Vitest with focus forbidden and parses its JSON reporter to count skipped and todo tests per file. Playwright discovery uses `--list --forbid-only --reporter=json` and counts declared skips by expected status, without launching journeys.

**No new skips** (#23, amended 2026-11-21). Ticket references earn no credit. A file's count is its runtime skips (Vitest skipped/todo tests, Playwright specs listed as skipped) plus every skip the runners cannot observe. It may never exceed the file's baseline, and baselines only go down: 52 legacy skips across ten Playwright files. A count above its allowance fails. A count below it fails until the allowance is lowered to match. New files must have zero. Fix or delete a failing test instead of skipping it. Focus (`.only`) always fails, with or without a ticket.

Playwright's list never runs test bodies, hooks or fixtures, so a TypeScript scan of `tests/` and every `*.spec.*`/`*.test.*` file is the backstop. It counts each `skip`, `fixme`, `todo`, `skipIf` and `runIf` reference (property, string-literal bracket access, alias or destructuring). The only exception is a direct declaration such as `test.skip('title', fn)`, `describe.skip('title', fn)` or `it.todo('title')` made at file scope or inside describe callbacks; the runners report those. Conditional calls (`test.skip(condition, reason)`, `skipIf`, `runIf`) count even when inactive. Skips inside test bodies, hooks, helpers, nested functions or classes count too. The scan is static: it does not follow computed member names, a `describe` alias bound to a test function, or code that loads a module from inside a test body. Sections below that describe ticket credit are historical.

Initial CI calibration: [run 44026799450](https://github.com/wescodess/cadet2/actions/runs/44026799450) passed every command except lint. The inherited Nitro lint project used WebWorker libraries, leaving browser DOM types unresolved in CI. The dedicated lint project now explicitly loads ESNext, DOM and DOM.Iterable. The initial measurement was 1,736 findings; the corrected measurement is 1,688. Its initial adoption baseline was recaptured with those libraries: two already-existing optional-chain findings became visible while spurious unsafe DOM findings disappeared. Both affected component files are byte-identical to `fe2b4a4`; no application code was changed to clear the baseline. This correction is part of the initial adoption inventory; subsequent integration changes remain subject to the no-increase ratchet.

Gitleaks is a native binary rather than a devDependency. The gate downloads the official 8.30.1 archive into a private temporary file, verifies its pinned SHA-256, then atomically publishes `.cache/gitleaks/<archive-sha256>.tar.gz`. A verified cache hit is reused without network access or mutation. Corrupt entries are replaced only by verified downloads. Every invocation extracts into the private scanner temporary directory and checks the executable checksum and pinned version before use. The scanner directory is removed on success or failure, so executables never enter retained artifacts. Scans use a private default-rules configuration and ignore `gitleaks:allow` comments. Root `.gitleaksignore` and `.gitleaks.toml` files are forbidden because the scanner can otherwise apply repository suppressions. Linux x64 (CI) and macOS arm64 are supported; other platforms fail explicitly. No Docker daemon, hosted scanner account or paid service is required.
